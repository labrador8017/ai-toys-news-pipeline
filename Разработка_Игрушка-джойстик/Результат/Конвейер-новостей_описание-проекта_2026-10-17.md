# Конвейер новостей об ИИ-игрушках: от поиска до публикации на сайте

Проект «Интерактивная сказка» (игрушка-джойстик) · описание проекта · 17.10.2026

Связанные документы: план развития на 30 дней (`Игрушка-джойстик_план-развития-30-дней_2026-10-16.md`), инструкция по размещению сайта (`Сайт_инструкция_размещение-рег-ру_2026-10-16.md`).

---

## 1. Название

**«Конвейер новостей об ИИ-игрушках»**: одна команда даёт проверенную новость на сайте с картинкой и готовые посты для соцсетей.

## 2. Проблема

- Сайт-лендинг игрушки-джойстика нужно «прогревать» до запуска первой партии. Для этого нужен регулярный поток полезных новостей для родителей: 2–3 в неделю.
- Вручную одна новость занимает **40–60 минут**: найти свежую новость, сверить дату и факты по нескольким источникам, написать текст, сделать картинку, сверстать карточку, выложить на хостинг.
- Тема чувствительная: дети, безопасность, персональные данные, законы. Одна фактическая ошибка подрывает доверие родителей, то есть будущих покупателей. Поэтому проверка фактов должна быть встроенной и обязательной, а не «по возможности».
- Если не автоматизировать, публикации будут нерегулярными, а время руководителя уйдёт на рутину.

## 3. Пользователь

| Кто | Что получает |
|---|---|
| **Родители детей 4–10 лет**, читатели сайта (основная аудитория) | Короткие проверенные новости об ИИ-игрушках с практическим советом и ссылкой на первоисточник |
| **Владелец проекта** (оператор конвейера) | Одна команда вместо часа ручной работы. От него нужны только две проверки: годится ли новость и можно ли выкладывать |
| **Подписчики соцсетей** (Telegram, MAX, ВКонтакте; позже) | Те же новости в формате постов под каждую площадку |

## 4. Основная функция

Конвейер из шести шагов. Каждый шаг делает отдельный инструмент со своим входом и выходом, поэтому любой шаг можно запустить и проверить отдельно.

```text
 команда «сделай новость»
        │
 [1] Поиск ──► [2] Валидация ──► ✋ проверка №1 ──► [3] Текст ──► [4] Картинка ──► [5] Вёрстка ──► ✋ проверка №2 ──► [6] Публикация
   субагент      субагент                       субагент      Python + API     скилл                             Python + SFTP
                                                                GigaChat                                          на Рег.ру
                                                     └──► (позже) [7] Соцсети: Telegram / VK / MAX через API
```

| # | Шаг | Вход | Выход | Инструмент | Статус |
|---|---|---|---|---|---|
| 1 | **Поиск** | Тема (или пусто — «самое свежее»), реестр кандидатов | Справка-новость `.md` с таблицей фактов и статусами проверки; строки в реестре кандидатов | Субагент `news-ai-toys-search` (WebSearch, WebFetch) | ✅ есть |
| 2 | **Валидация** | Справка `.md` | Заключение «годится / доработать / отказ» с замечаниями | **Новый** субагент `news-ai-toys-validator`. Независимо перепроверяет: свежесть ≤14 дней по первоисточнику, 2+ независимых источника на ключевые факты, нет повтора, нет утверждений о компаниях без оговорки «по данным…» | 🔲 сделать |
| 3 | **Текст** | Справка `.md` | JSON поста по схеме `ai-toys-post/v1`: текст для сайта, посты TG/MAX/VK, промпт и негатив-промпт для Kandinsky, список неподтверждённого | Субагент `news-ai-toys-content-writer` | ✅ есть |
| 4 | **Картинка** | Поле `image` из JSON (prompt, negative_prompt, aspect_ratio) | `.jpg` рядом с JSON поста (копию в `Сайт/assets/img/news/` делает скилл вёрстки) | Python-скрипт `gigachat_img.py`: GigaChat API, встроенная функция рисования (Kandinsky) — запрос «Нарисуй…», получение id файла, скачивание JPG | ✅ есть |
| 5 | **Вёрстка** | JSON поста и картинка | Карточка в `Сайт/news.html` по дате, с тегом, советом родителям, источником | Скилл `news-ai-toys-site` | ✅ есть |
| 6 | **Публикация** | Изменённые файлы сайта | Файлы на хостинге и лог выкладки | **Новый** Python-скрипт `deploy_site.py`: сравнивает локальные и удалённые файлы, показывает список, выкладывает по SFTP только после подтверждения | 🔲 сделать |
| — | **Оркестратор** | Команда (+ необязательная тема) | Проход шагов 1–6 с двумя остановками на проверку | **Новый** скилл `news-ai-toys-pipeline` (вызывает субагентов, скилл и скрипты по очереди) | 🔲 сделать |
| 7 | **Соцсети** (будущее) | `platforms` из JSON и картинка | Посты в каналах | Скрипт публикации через Telegram Bot API, VK API, MAX Bot API | ⏳ после создания каналов |

**Точки ручного контроля:**
- **✋ проверка №1** (после валидации): владелец подтверждает выбор новости или просит взять другую из реестра (статус `резерв`).
- **✋ проверка №2** (перед публикацией): вычитка карточки в браузере и подтверждение списка файлов к выкладке.

Без подтверждения конвейер ничего не публикует.

## 5. Формат результата

После одного прогона пользователь получает:

1. **Опубликованную новость на сайте**: карточку на странице «Новости» с заголовком, датой, тегом, текстом, советом «Наш совет» для родителей, ссылкой на первоисточник и сгенерированной картинкой.
2. **Справку с проверкой фактов**, `Документы/Новости/ИИ-игрушки_новость_<тема>_<дата>.md`: какие факты подтверждены, какие нет, все источники с датой получения.
3. **Реестр кандидатов**, `Документы/Новости/ИИ-игрушки_кандидаты_реестр.md`: все рассмотренные новости с решением (выбрана / резерв / отказ). Резерв служит запасом на следующие прогоны.
4. **JSON поста**, `Результат/Посты/ИИ-игрушки_пост_<тема>_<дата>.json`: готовые тексты для Telegram, MAX, ВКонтакте (пока для ручной публикации).
5. **Картинку**, `Результат/Посты/ИИ-игрушки_пост_<тема>_<дата>.jpg`.
6. **Лог публикации**: какие файлы выложены, когда, результат. Плюс коммит в git с понятным описанием.

## 6. Минимальный функционал (MVP)

**MVP:** одна команда запускает шаги 1–6 с двумя ручными проверками.

| Этап | Что делаем | Готово, когда |
|---|---|---|
| 1 | Субагент-валидатор `news-ai-toys-validator` | Ловит в тестовой справке намеренно испорченную дату и факт с одним источником |
| 2 | Скрипт `gigachat_img.py` | По JSON любого существующего поста получается картинка в нужных папках (✅ 17.10.2026: пробная картинка к посту «калифорния-мораторий») |
| 3 | Скрипт `deploy_site.py` | Пробный прогон показывает список файлов; после «да» сайт обновлён на Рег.ру |
| 4 | Скилл-оркестратор `news-ai-toys-pipeline` | Сквозной прогон на новой новости, ручное время ≤10 минут |

**Критерии успеха** (из плана развития на 30 дней):
- 8–12 новостей на сайте за месяц (2–3 в неделю);
- не больше 10 минут ручного времени на новость (сейчас 40–60);
- 0 фактических ошибок: каждый ключевой факт подтверждён по двум источникам, спорное помечено.

**Будущие версии:**
- **Соцсети:** автопостинг в Telegram (Bot API), ВКонтакте (VK API), MAX (Bot API), когда появятся каналы. Только после ручного подтверждения.
- **Расписание:** поиск 2 раза в неделю по Cron; новость попадает в «очередь на проверку», владелец получает уведомление.
- **Сайт:** отдельная страница на каждую новость (для поисковиков), RSS-лента, sitemap, разметка Open Graph для красивых превью в соцсетях.
- **Метрики:** сбор охватов и посещаемости, недельная сводка.
- **Рассылка:** подписка на новости и сбор заявок на первую партию игрушек (после политики обработки ПДн).

## 7. Технологии

| Слой | Что используется |
|---|---|
| Агентная среда | **Claude Code**: субагенты (`.claude/agents/*.md`) для поиска, валидации и текста; скиллы (`.claude/skills/*/SKILL.md`) для вёрстки и оркестрации; Cron для расписания (в будущем) |
| Язык скриптов | **Python 3**: стандартная библиотека (`urllib`, `ssl`, `json`, `csv`, `pathlib`) для GigaChat API, `paramiko` (SFTP-выкладка) |
| Генерация картинок | **GigaChat API** (Сбер), встроенная функция рисования text2image (Kandinsky): OAuth-токен по «ключу авторизации» (живёт 30 мин) → `POST /chat/completions` с `"function_call": "auto"` → id картинки в теге `<img>` → `GET /files/{id}/content` (JPG). HTTPS проверяется по корневому сертификату НУЦ Минцифры (`certs/`), проверка SSL не отключается |
| Хостинг | Виртуальный хостинг **Рег.ру**, тариф **Host-0** (панель ispmanager), доступ по **SFTP** (работает поверх SSH, данные шифруются; есть на всех тарифах, кроме Host-Lite) |
| Сайт | Статический HTML/CSS/JS без сборки (`Результат/Сайт/`) |
| Форматы данных | Справка — **Markdown**; пост — **JSON** по схеме `ai-toys-post/v1`; реестр кандидатов — таблица Markdown; картинки — JPG |
| История и откат | **git**: коммит после каждого прогона |
| Секреты | Файл `.env` (ключ GigaChat, доступ SFTP) в `.gitignore`, ключ GigaChat также в переменной пользователя Windows; в репозиторий и в чат не попадает |
| Будущее | Telegram Bot API, VK API, MAX Bot API |
