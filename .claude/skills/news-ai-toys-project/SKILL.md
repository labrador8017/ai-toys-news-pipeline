# Проект «Конвейер новостей об ИИ-игрушках» — как с ним работать

Одна команда в Claude Code проводит новость по цепочке: поиск → проверка фактов → посты (Telegram, MAX, ВК) → картинка → карточка на сайте → выкладка на хостинг. Интерфейс — локальная страница-пульт. Подробно для людей — `Разработка_Игрушка-джойстик/README.md`; этот скилл — для тебя (Claude), чтобы работать с репозиторием без лишних поисков.

Пути ниже — от корня репозитория (папка, где лежит `.claude/`). Обозначения: `P/` = `Разработка_Игрушка-джойстик/`, `S/` = `P/Документы/Скрипты/`. В инструкциях агентов и скиллов корень записан абсолютно (`D:\myai\…`) — при развёртывании в другой папке его заменяют (см. «Развернуть у себя»).

## 1. Карта проекта

| Что | Где | Роль |
|---|---|---|
| Оркестратор | `.claude/skills/news-ai-toys-pipeline/SKILL.md` | Ведёт новость по шагам, 2 остановки на подтверждение |
| Поиск | `.claude/agents/news-ai-toys-search.md` | Черновик справки + реестр кандидатов |
| Проверка | `.claude/agents/news-ai-toys-validator.md` | Статусы фактов, вердикт годится / доработать / отказ |
| Посты | `.claude/agents/news-ai-toys-content-writer.md`, `.claude/skills/news-ai-toys-post/` | JSON по схеме `ai-toys-post/v1` |
| Сайт | `.claude/skills/news-ai-toys-site/SKILL.md` | Карточка в `news.html` |
| Этот скилл | `.claude/skills/news-ai-toys-project/` | Структура, проверка, экспорт (`scripts/`) |
| Проверка длин | `S/post_check.py` | Telegram ≤950, MAX ≤1200, ВК ≤1500 (с хэштегами) |
| Картинки | `S/gigachat_img.py` | GigaChat API (встроенный Kandinsky), сертификат `S/certs/` |
| Выкладка | `S/deploy_site.py` | SFTP на Рег.ру: просмотр → `--upload` |
| Пульт | `S/build_dashboard.py` → `P/Результат/Пульт-конвейера.html` | Интерфейс: статусы, тексты постов с «Копировать» |
| Доступы | `S/.env` (не в git), образец `S/.env.example` | SFTP_*, GIGACHAT_* |
| Данные | `P/Документы/Новости/` (справки, `ИИ-игрушки_кандидаты_реестр.md`), `P/Результат/Посты/` (JSON + .jpg), `P/Результат/Сайт/` | |
| Журналы | `S/журнал_картинок.csv`, `S/журнал_выкладки.csv` | Коммитятся (история) |
| Документация | `P/README.md`, `P/INDEX.md`, `P/Результат/Конвейер-новостей_описание-проекта_*.md`, `P/Документы/Конвейер-новостей_инструкция-тестирования_*.md` | |

Остальное в `P/` (ТЗ, анализ рынка, PRD, план развития) — смежные документы проекта игрушки, конвейер от них не зависит.

## 2. Форматы данных (контракты между шагами)

Ломать их нельзя — на них завязаны соседние шаги, пульт и проверка.

- **Справка** `ИИ-игрушки_новость_<тема>_<ГГГГ-ММ-ДД>.md`: шапка со строками `- Дата публикации: ГГГГ-ММ-ДД` и `- Проверка: не проведена` | `- Проверка: ГГГГ-ММ-ДД — <вердикт>`; разделы `## Первоисточник` (первая ссылка = URL источника), `## Ключевые факты` (таблица: № | Факт | Статус | Источники), `## Не подтверждено`, `## Заключение проверки`. Статусы: `на проверке`, `подтверждено`, `по данным компании`, `по данным <кто>`, `не подтверждено`. Справки до 17.10.2026 — старый формат без строки «Проверка».
- **Реестр кандидатов**: таблица `| Дата поиска | Заголовок | Дата публикации | Ступень | Источник | Решение / причина | Справка |`, только дописывается. Решения: `выбрана`, `резерв`, `отказ: …`, `отказ после проверки: …`.
- **Пост** `ИИ-игрушки_пост_<тема>_<дата>.json`: `schema_version: "ai-toys-post/v1"`, `source{title,url,published_at,retrieved_at}`, `summary`, `unverified[]`, `image{generator,prompt,negative_prompt,aspect_ratio}`, `platforms{telegram,max,vk}{content,hashtags[]}`. Картинка — `.jpg` с тем же именем рядом.
- **Карточка сайта** (`news.html`, лента `<section class="sheet news">`): `<article class="post [post--pic] reveal" id="<slug>">`, `<img class="post__pic">`, `<time datetime>`, `post__tag`, `post__title`, `post__tip`, `<a class="post__src" href="<source.url>">`. Новые сверху, `source.url` уникален — по нему пульт связывает пост и карточку.

## 3. Развернуть у себя

Когда просят «разверни проект» (обычно коллега в выгруженном комплекте):

1. **Корень.** Найди, где лежит `.claude/` и `Разработка_Игрушка-джойстик/`. Если это не `D:\myai` — предложи заменить `D:\myai` на фактический путь во всех `.md` в `.claude/agents/news-ai-toys-*`, `.claude/skills/news-ai-toys-*` и в `P/README.md`, `P/Документы/*.md`; покажи список файлов и замени после согласия.
2. **Python 3.10+**: `python --version`. Зависимость одна: `python -m pip install paramiko` (нужна только для выкладки; спроси перед установкой).
3. **`.env`**: скопируй `S/.env.example` → `S/.env` (только если `.env` ещё нет). Значения человек вписывает сам — ты файл не читаешь и ключи в чат не просишь. Подскажи: `SFTP_HOST` — IP сервера (не адрес панели), `SFTP_REMOTE_DIR` — папка сайта (`www/<домен>`), `GIGACHAT_AUTH_KEY` — ключ из developers.sber.ru. В Блокноте сохранять как «Все файлы», иначе получится `.env.txt`.
4. **Проверка ключей и доступа** (выполнить и показать вывод):
   ```
   python "S/gigachat_img.py" --check
   python "S/deploy_site.py" --check
   ```
   Первое подключение к хостингу покажет отпечаток ключа сервера — `--trust-new-host` только с согласия человека. Зависание с `Error reading SSH protocol banner` — обычно VPN/антивирус: см. `P/README.md`, «Если что-то не работает».
5. **Проверка проекта**: `python ".claude/skills/news-ai-toys-project/scripts/project_check.py"`.
6. **Новые агенты и скиллы** видны после перезапуска Claude Code.
7. Итог — короткая таблица: что готово, что осталось сделать человеку.

## 4. Запуск

| Задача | Как |
|---|---|
| Новость целиком | «сделай новость про ИИ-игрушки» → скилл `news-ai-toys-pipeline` |
| С середины | «запусти конвейер по справке <путь>» / «… с поста <JSON>» / «выложи сайт» |
| Пульт | `python "S/build_dashboard.py" --open` |
| Сайт локально | `python -m http.server 8765 --directory "P/Результат/Сайт"` (в фоне) → `http://localhost:8765/news.html`; после проверки остановить |
| Длины поста | `python "S/post_check.py" <JSON>` |

Все скрипты сами находят свои папки (пути от расположения файла) — запускать можно из любого каталога. Вывод в UTF-8 при запуске из агента настроен в самих скриптах.

## 5. Как вносить изменения

Перед правкой — `git status` (не смешивай чужие незакоммиченные изменения со своими). После правки — §7 проверка, затем §6 документация, затем коммит.

| Меняешь | Что ещё обновить |
|---|---|
| Формат справки / статусы | `news-ai-toys-search.md` (шаблон), `news-ai-toys-validator.md`, `news-ai-toys-content-writer.md` (как читает статусы), `S/build_dashboard.py` (`read_briefs`), §2 этого скилла |
| Схема поста JSON | `news-ai-toys-content-writer.md` и `news-ai-toys-post/SKILL.md` (оба шаблона одинаково), `S/post_check.py`, `S/build_dashboard.py`, `news-ai-toys-site/SKILL.md`, §2 |
| Лимиты длин | `LIMITS` в `S/post_check.py` + раздел площадки в обоих шаблонах постов + README |
| Шаги цепочки | `news-ai-toys-pipeline/SKILL.md`, схема в `P/README.md`, таблица в описании проекта, инструкция тестирования |
| Вёрстка карточки | `news-ai-toys-site/SKILL.md` + существующие карточки в `news.html` единообразно; `id`/`post__src` не трогать |
| Скрипт | docstring вверху (запуск и флаги), раздел «Запуск» в README, строка в `P/INDEX.md` |
| Новый агент/скилл | frontmatter: `name` = имя файла/папки; `description` в кавычках, если в нём есть «: »; добавить в §1, в `REQUIRED`/`CLAUDE_ITEMS` скриптов этого скилла, в README «Состав» |

Правила правки:
- Пиши файлы инструментами Write/Edit. **Не вставляй пути с обратным слэшем через bash-heredoc или `python -c`** — в этой среде `\b`, `\n` в путях превращаются в управляющие символы (`project_check.py` их ловит).
- Описание агента/скилла с «: » без кавычек ломает YAML — скилл теряет описание и хуже вызывается.
- Не перезаписывай справки, посты, картинки и строки реестра — это история; новые версии — новыми файлами.
- `.env`, `known_hosts` не читать, не выводить, не коммитить.

## 6. Обновление README и INDEX

`P/README.md` — для людей; держи его в синхронизации с фактом:

| Раздел README | Источник правды |
|---|---|
| «Что делает» (схема) | шаги в `news-ai-toys-pipeline/SKILL.md` |
| «Интерфейс — пульт» | `S/build_dashboard.py` (что реально показывает) |
| «Подготовка» | `S/.env.example`, зависимости скриптов |
| «Запуск» | триггеры оркестратора, флаги скриптов (docstring) |
| «Пользовательский сценарий» | точки остановки оркестратора |
| «Что получается на выходе» | имена файлов из шаблонов агентов и скриптов |
| «Если что-то не работает» | реальные сообщения об ошибках скриптов |
| «Состав» | §1 этого скилла |

Порядок: прочитай README целиком → сверь каждый затронутый раздел с источником → правь точечно (Edit), стиль — короткие таблицы и команды → проверь ссылки (`project_check.py` проверяет относительные ссылки README/INDEX). В `P/INDEX.md` — строка на каждый новый файл (одна строка описания). Дата в именах файлов `Результат/` — ГГГГ-ММ-ДД (исключение — живой `Пульт-конвейера.html`).

## 7. Проверка ошибок

```
python ".claude/skills/news-ai-toys-project/scripts/project_check.py"
```
Код 1 = есть ошибки. Проверяет: обязательные файлы; frontmatter агентов/скиллов (`name`, кавычки в `description`); управляющие символы в текстах; синтаксис Python; что `.env`/`known_hosts`/`__pycache__` не в git и нет заполненных ключей; JSON постов и лимиты длин; ссылки на файлы в страницах сайта, уникальность карточек, порядок дат, `[уточнить]` на сайте; битые ссылки README/INDEX, неупомянутые в INDEX файлы, устаревший пульт; справки, ждущие проверки.

Предупреждения (длинный пост, нет картинки, устаревший пульт) не блокируют коммит, но о них нужно сказать человеку. Дополнительно при сомнениях: открыть `news.html` и пульт в браузере (Playwright) и сделать скриншот.

## 8. Подготовка к публикации и передаче коллегам

1. `project_check.py` — без ошибок.
2. `python "S/build_dashboard.py"` — пульт свежий.
3. `git status` чистый, всё нужное закоммичено (коммит — по правилам `CLAUDE.md` корня, если он есть).
4. Комплект:
   ```
   python ".claude/skills/news-ai-toys-project/scripts/export_project.py" --zip
   python ".claude/skills/news-ai-toys-project/scripts/export_project.py" --root "C:\path\for\colleague" --zip
   ```
   Собирается в `P/tmp/export/news-ai-toys_<дата>/` (+ .zip): проект без секретов и личных документов, агенты, скиллы, `.gitignore` и корневой `README.md` (README проекта со ссылками от корня + раздел «Развернуть у себя» — его GitHub показывает на главной). Имя папки — `--name` (например, имя репозитория). Существующую папку не перезаписывает. Бизнес-документы — флагом `--with-business-docs`, только по просьбе владельца.
5. Перед отправкой — открой корневой `README.md` комплекта и выборочно 2–3 файла комплекта; убедись, что `.env` в комплекте нет.
6. Предупреди владельца:
   - иллюстрации сайта вне `assets/img/news/` — временные заглушки, часть с действующими правами (PRD, раздел о правах): для публичной публикации заменить;
   - в справках и постах — материалы о реальных компаниях с атрибуцией «по данным …»; не убирать оговорки при пересказе;
   - в текстах агентов фигурирует имя владельца как заказчика — при передаче в другую команду можно заменить.
7. Публикация на хостинг — только `deploy_site.py` и только с явного согласия; push в удалённый репозиторий — только по просьбе.
